O que é Análise e Projeto?

A fase de Análise e Projeto (Analysis and Design) é um dos pilares da Engenharia de Software. Ela atua como a ponte entre a concepção inicial de uma ideia (o problema do cliente) e a implementação do código fonte (a solução técnica).

Resumidamente, dividimos esta disciplina em duas grandes perguntas:

  • Análise: "O que o sistema deve fazer?" (Foco no problema)
  • Projeto: "Como o sistema vai fazer isso?" (Foco na solução)

Compreendendo o Domínio

Na análise, o objetivo é entender as necessidades dos usuários e as regras de negócio. O resultado dessa fase é uma especificação clara de requisitos.

  • Requisitos Funcionais: Descrevem as ações que o sistema deve executar (ex: "O sistema deve emitir nota fiscal").
  • Requisitos Não-Funcionais: Descrevem qualidades do sistema (ex: "O sistema deve carregar em menos de 2 segundos" ou "O sistema deve ter autenticação 2FA").
  • Ferramentas comuns: Diagramas de Caso de Uso (UML), Histórias de Usuário (User Stories), Entrevistas com stakeholders.

Arquitetando a Solução

O projeto (design) pega os requisitos levantados na análise e define a arquitetura técnica que será programada pelos desenvolvedores.

  • Projeto de Arquitetura: Escolha de tecnologias, padrões de projeto (Design Patterns como MVC, Singleton) e infraestrutura.
  • Projeto de Banco de Dados: Modelagem de Entidade-Relacionamento (MER), normalização de tabelas e definição de esquemas.
  • Projeto de Interface (UI/UX): Criação de wireframes, protótipos navegáveis e definição da jornada do usuário.
  • Ferramentas comuns: Diagrama de Classes, Diagrama de Sequência, Figma, Modelagem de Dados.

Por que essa etapa é vital?

Mudar uma regra de negócio ou corrigir um erro de arquitetura durante a fase de análise custa 1x. Corrigir esse mesmo erro depois que o software já está programado e em produção pode custar até 100x mais. Planejar evita retrabalho, atrasos e estouros de orçamento.
